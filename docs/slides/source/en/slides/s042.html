Architecture

One sketch, two entry points

Every Arduino program has the same shape. Esp32_drone.ino is no different.

setup()

Runs once at power-on. Starts the hardware, loads saved settings, calibrates the gyro.

loop()

Runs forever, once every 4 ms. Reads, decides, drives the motors.

No RTOS tasks

The flight code does not create its own threads. One loop, one order.

Example

Like a cook following one recipe card from top to bottom, again and again, instead of several cooks working at once.

Why no separate tasks? Many flight controllers use an RTOS with tasks for sensors, control and radio. This firmware keeps everything in one loop so a learner can read it top to bottom and know exactly what runs when. The Wi-Fi and Bluetooth stacks still run in the background inside the ESP32 core.
