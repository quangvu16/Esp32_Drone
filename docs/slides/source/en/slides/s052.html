Saving settings: NVS flash

void cfgSave() {
  float g[9] = { pid_p_gain_roll, ... };   // 9 gains
  uint16_t f[3] = { hover_thrust, takeoff_ms, land_ms };
  nvs.putBytes("pid",  g, sizeof(g));
  nvs.putBytes("fcfg", f, sizeof(f));
}

NVS = non-volatile storage: a small key-value store in the ESP32 flash.

Raw floats: a read-back is byte-identical to what was written — no rounding.

Refused while armed: erasing flash stalls both cores for milliseconds.

Example

Tune roll_kp to 1.5 on the phone, land, press Save → it survives the next power-off.

Architecture · 52 · Source: Esp32_drone.ino cfgSave(), cfgLoad(), FC_CMD_SAVE

Why refuse SAVE while armed? A flash erase can pause the CPU for several milliseconds, longer than one 4 ms loop. In the air, a missed loop means a missed correction. cfgLoad() also clamps the loaded values, so a corrupted save cannot load an absurd gain.
