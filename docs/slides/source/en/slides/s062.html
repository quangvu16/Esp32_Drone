Gyro calibration: measure the bias at rest

int32_t sx = 0, sy = 0, sz = 0;
for (int i = 0; i < 2000; i++) {
  mpuReadRaw();
  sx += raw_gx; sy += raw_gy; sz += raw_gz;
  delay(3);
}
gyro_x_cal = sx / 2000;   // average = bias
gyro_y_cal = sy / 2000;
gyro_z_cal = sz / 2000;

A still gyro should read 0, but every chip reads a little off — the bias.

2,000 samples × 3 ms ≈ 6 seconds. The average is the bias, subtracted every loop.

Keep the drone flat and still or the bias will be wrong.

Example

Bias 0.3 °/s not removed → after 60 s the heading is off by 0.3 × 60 = 18°.

Motion sensor · 62 · Source: Esp32_drone.ino mpuCalibrateGyro()

Why does bias matter so much? The angle is the sum of the gyro rate over time. A bias of 0.3 °/s left in for 60 seconds becomes an 18 degree error in heading. Moving the drone during calibration bakes a false rotation into every flight until the next power-on.
