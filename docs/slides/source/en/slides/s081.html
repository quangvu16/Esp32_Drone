A real bug: the self-level sign

One character, + or −, decided whether the drone could fly.

Before (bug)

roll_setpoint = sp_roll_rate + roll_level_adjust

Tilted +5° → asks for +75 °/s: MORE tilt

Positive feedback: the drone flipped

After (fix)

roll_setpoint = sp_roll_rate − roll_level_adjust

Tilted +5° → asks for −75 °/s: back to level

test/level_test.cpp simulates both

level_test keeps the old formula as a negative control, so the test cannot pass by accident.

PID control · 81 · Source: Esp32_drone.ino loop() comment; test/level_test.cpp

The story: the old code added the level term. With a perfect rate loop, any tilt commanded more tilt the same way — positive feedback — and the drone flipped within a fraction of a second of take-off. The fix is one character. The lesson is bigger: write a tiny simulation for every sign that matters, and keep the wrong version in the test to prove the test can fail.
