Framing and the checksum

uint8_t crtpChecksum(const uint8_t *data, size_t len) {
  uint32_t sum = 0;
  for (size_t i = 0; i < len; i++) sum += data[i];
  return (uint8_t)(sum & 0xFF);
}
// on receive (UDP / SPP):
if (crtpChecksum(data, len - 1) != data[len - 1]) return;
crtpDispatch(data, len - 1);
crtp_last_rx_ms = millis();     // the link is alive

Over UDP and SPP, each packet ends with one checksum byte: the low 8 bits of the sum.

A bad checksum → the packet is dropped silently.

A good packet also refreshes crtp_last_rx_ms, used by the failsafe.

Example

Packet 0x70 0x02 → sum 0x72 → checksum byte 0x72. Sent on the wire: 70 02 72.

Why such a simple checksum? It catches most single-byte errors and costs almost nothing. UDP already has its own checksum, so this is mainly protection for the Bluetooth serial link. BLE packets arrive already framed by the BLE stack, so they skip this step.
