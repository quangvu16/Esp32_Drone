Logging: streaming data to the phone

The app picks variables from the log TOC and asks for them at a period. The drone then sends them by itself.

Up to 3 blocks

Each with up to 12 variables and its own period (in 10 ms steps).

Groups

pm.vbat, stabilizer, controller, motor, flight, nav, pid (P/I/D per axis).

Packet

block id, 24-bit timestamp, then the values straight from the live variables.

Example

Block 1, period 25 (× 10 ms = 250 ms): pm.vbat, flight.mode, flight.armed → 4 packets a second.

Radio inputs · 108 · Source: Esp32_drone.ino LOG_TOC, logSendData(), logUpdate()

Why stream instead of asking each time? Asking would double the radio traffic and add a round-trip delay. Streaming also reads all values in one go, so one packet is consistent. The app's Standard config now asks for battery, mode, armed, auto state, roll and pitch every 250 ms.
