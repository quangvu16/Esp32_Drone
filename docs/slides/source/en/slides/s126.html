Modes and safety

Why a repeated TAKEOFF is ignored

// A retransmitted TAKEOFF must not restart the ramp
if (armed && flight_mode == MODE_AUTO &&
    (auto_state == AUTO_TAKEOFF || auto_state == AUTO_HOLD))
  return true;                       // already done
// Flying in another mode: never ramp from zero
bool spinning = motor_rf > 1000 || motor_rr > 1000 || ...;
if (armed && spinning) return false;

The app resends TAKEOFF every 500 ms until it sees the ack.

If the ack was lost, a second TAKEOFF arrives while climbing.

Restarting the ramp would drop thrust to zero — and drop the drone.

Modes and safety · 126 · Source: Esp32_drone.ino flightTakeoff()

This is principle 3 from slide 54 in action: commands must be idempotent. The first check makes a repeat harmless. The second refuses TAKEOFF while flying in another mode, because a ramp from zero thrust in the air is never what anyone wants.
