A real bug: the accelerometer scale

Two numbers, 1,800 lines apart, had to agree. They did not.

Before (bug)

NAV_ACC_LSB_PER_G = 16384 (the ±2 g scale)

Sensor actually set to ±8 g (4096 per g)

Every acceleration read 4× too small → position 4× too small

After (fix)

NAV_ACC_LSB_PER_G = 4096

Comment: must match MPU_REG_ACCEL_CFG in mpuInit()

run.sh reads both values and fails if they disagree

Navigation · 133 · Source: Esp32_drone.ino #define NAV_ACC_LSB_PER_G; test/run.sh

Two constants far apart in the file described the same fact, and one was changed without the other. The drone believed it had moved 1 m when it had moved 4 m, so FOLLOW overshot badly. The guard in run.sh maps each ACCEL_CFG value to its scale and refuses to continue if the #define does not match.
