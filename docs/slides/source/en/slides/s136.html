Turning with the drone: two rotations

const float yaw_rel = (heading_deg - heading_ref_deg)
                      * NAV_HEADING_SIGN * DEG_TO_RAD;
// body -> launch (navUpdate)
ax_w = fwd * cy - left * sy;
ay_w = fwd * sy + left * cy;
// launch -> body (navSetpoints)
body_fwd  =  ux * cy + uy * sy;
body_left = -ux * sy + uy * cy;

The drone may yaw after launch. Acceleration is measured in the body, but position lives in the launch frame.

One rotation goes body → launch, the other is its exact reverse.

NAV_HEADING_SIGN = −1 makes the gyro's heading direction match the left-positive frame.

Navigation · 136 · Source: Esp32_drone.ino navUpdate(), navSetpoints(); test/yawrot_test.cpp

Why a sign constant? heading_deg grows in the direction the gyro calls positive, but the launch frame measures angles from +x toward +y, which is to the left. If those two disagree, every rotation turns the wrong way. yawrot_test.cpp is built with the sign read straight from the sketch, so it tests the configuration that actually runs.
