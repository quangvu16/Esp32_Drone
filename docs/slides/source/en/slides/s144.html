Adding a test of your own

1

Pick one formula or rule you are about to change, and copy those lines into a new test .cpp.

2

Write cases with known answers, worked out by hand: a good case and a bad case.

3

Keep the old version as a negative control so the test can be seen to fail.

4

Add a check '…' line to run.sh for each copied line, and a build-and-run step.

5

Run sh run.sh, then change the sketch, then run it again.

Testing · 144 · Source: Esp32_drone/test/run.sh pattern

This order — test first, then change the code — is test-driven development in its simplest form. The negative control is the step learners skip most often, and it is the one that proves your test is actually testing something.
