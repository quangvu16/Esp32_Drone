Đóng khung và checksum

uint8_t crtpChecksum(const uint8_t *data, size_t len) {
  uint32_t sum = 0;
  for (size_t i = 0; i < len; i++) sum += data[i];
  return (uint8_t)(sum & 0xFF);
}
// on receive (UDP / SPP):
if (crtpChecksum(data, len - 1) != data[len - 1]) return;
crtpDispatch(data, len - 1);
crtp_last_rx_ms = millis();     // the link is alive

Qua UDP và SPP, mỗi gói kết thúc bằng một byte checksum: 8 bit thấp của tổng.

Checksum sai → gói bị bỏ im lặng.

Gói tốt cũng cập nhật crtp_last_rx_ms, được failsafe dùng.

Ví dụ

Gói 0x70 0x02 → tổng 0x72 → byte checksum 0x72. Trên đường truyền: 70 02 72.

Vì sao checksum đơn giản vậy? Nó bắt được phần lớn lỗi một byte và gần như không tốn gì. UDP đã có checksum riêng, nên đây chủ yếu bảo vệ đường Bluetooth nối tiếp. Gói BLE đến đã được ngăn xếp BLE đóng khung, nên bỏ qua bước này.
